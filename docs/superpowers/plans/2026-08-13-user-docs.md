- [ ] **Step 1: Tulis file `docs/ai-agent.md`**

Struktur dan isi (bahasa Indonesia, judul `# AI Agent Vexis — Panduan Coba`):

1. **Ringkasan** — paragraf: agent mengotomasi manajemen posisi DLMM Meteora: screening pool secara deterministik, LLM memutuskan `open`/`hold` per kandidat, eksekusi dibelakang guardrail deterministik yang tidak bisa di-bypass LLM, plus TP/SL, penanganan posisi out-of-range (OOR), learning bobot sinyal Darwinian, dan briefing harian.

2. **Requirements** — list:
   - Node.js 20+
   - Wallet Solana (hot wallet khusus, dana terbatas)
   - API key LLM OpenAI-compatible (default `https://api.openai.com/v1`, model default `gpt-4o-mini`)
   - Bot token Telegram + chat ID (untuk notifikasi)

3. **Setup** — langkah:
   - `npm install && npm run build`
   - `cp vexis.config.example.json vexis.config.json`
   - Edit `vexis.config.json`: isi `wallet`, `privateKey` (base64/base58, untuk on-chain), `rpcUrl`, `telegramBotToken`, `telegramChatId`, dan blok `agent` + `agent.llm`.
   - Blok config minimum yang berfungsi (code block JSON):

   ```json
   {
     "wallet": "YourSolanaWalletAddress",
     "privateKey": "base64-or-base58-private-key",
     "rpcUrl": "https://api.mainnet-beta.solana.com",
     "telegramBotToken": "123456:ABC-your-bot-token",
     "telegramChatId": "your-numeric-chat-id",
     "agent": {
       "enabled": false,
       "maxCandidates": 5,
       "maxSolPerPosition": 0.5,
       "maxTotalSol": 3,
       "maxOpenPositions": 4,
       "txCooldownMs": 300000,
       "poolCooldownMs": 86400000,
       "tpPct": 25,
       "slPct": -10,
       "llm": {
         "baseUrl": "https://api.openai.com/v1",
         "model": "gpt-4o-mini",
         "apiKey": "sk-..."
       }
     }
   }
   ```

   - `npm run bot` untuk menjalankan bot; daftar lengkap semua key di [Referensi Konfigurasi](config-reference.md).
   - Mulai agent: `/agent start` di Telegram. Status: `/agent status`.

4. **Cara kerja** — dari perspektif user:
   - Diagram alur satu kalimat: `Screening (deterministik) → LLM decide open/hold → validasi anti-halusinasi → guardrail (hard block) → createPosition`.
   - 4 job terjadwal (tabel): `cycle` (interval `max(txCooldownMs, 60s)`, buka posisi baru, full-LLM), `event` (30 detik, cek TP/SL deterministik), `oor` (`intervalMinutes` menit, cek TP/SL + posisi OOR via LLM), `briefing` (tiap hari 09:00 lokal, narasi LLM + fallback data mentah).
   - Arti notifikasi live (satu pesan diedit in-place): `🔎 screening pools...` → `⏳ N pools in cooldown` → `🔁 N already open` → `🧠 LLM: thinking...` → `🧠 LLM: N candidates → M decisions` → per keputusan `🚀` open / `➖` hold / `⛔` blocked → summary.
   - `llmStatus`: `ok` (LLM sukses), `skipped` (nol kandidat — normal), `failed` (LLM error → seluruh cycle di-skip, nol trade).
   - Guardrail yang bisa memblokir open (list): posisi duplikat (pool/base token sama), cooldown per pool, tx-cooldown, risiko (rugpull/wash/bundle/bot/top10/global fees/dev sold all/dex paid/price vs ATH), budget (`maxSolPerPosition`, `maxTotalSol`, `maxOpenPositions`).
   - Darwinian: bobot sinyal belajar dari PnL posisi yang sudah ditutup.

5. **Perintah Telegram** — tabel:

   | Perintah | Fungsi |
   |---|---|
   | `/agent start` | Mulai agent |
   | `/agent stop` | Hentikan agent |
   | `/agent status` | Status dashboard (default `/agent`) |
   | `/agent portfolio` | Portfolio + PnL |
   | `/agent journal [n]` | Journal, n baris (maks 20) |
   | `/briefing` | Briefing harian manual (read-only) |

   Catatan: notifikasi agent selalu terkirim (termasuk saat LLM gagal). Callback keyboard pada notifikasi: `📊 PnL` (detail posisi), `⚠️ Retry` (re-run TP/SL), `📒 Journal`, `🧼 Clear`.

6. **Monitoring** — list:
   - State: `.vexis-agent.json` (plans, cooldowns, executions, `enabled`, `running`, `llmStatus`).
   - Journal: `.vexis-agent-journal.jsonl` — satu baris JSON per cycle/aksi: `{ts, cycle, llmStatus, candidates: [{pool, poolName, heuristicScore, rationale, action, guardrail, blockedReason, execution, txSignature}]}`.
   - Web dashboard: halaman `/agent` menampilkan narasi + timeline journal (auto-refresh 30 detik).
   - State files gitignored — aman untuk secret, tapi jangan di-hapus saat agent berjalan.

7. **Risiko & batasan** — list:
   - Agent melakukan transaksi on-chain nyata — gunakan hot wallet khusus dengan dana terbatas.
   - LLM bisa salah: guardrail adalah lapisan terakhir; heuristic hanya memilih kandidat, LLM yang memutuskan.
   - LLM gagal → cycle di-skip (zero trade) — desain fail-safe.
   - OOR: LLM gagal → semua posisi di-hold (degraded), bukan auto-close.
   - Budget caps: `maxSolPerPosition`, `maxTotalSol`, `maxOpenPositions` — hard block.
   - Bot/agent tidak berjalan saat server mati; state persisten di file JSON.

8. **Link** — `[Referensi Konfigurasi](config-reference.md)`, `[Troubleshooting](troubleshooting.md)`, `[Prompt untuk AI Coding Agent](coding-agent-prompt.md)`, `[README](../README.md)`.

- [ ] **Step 1: Tulis file `docs/troubleshooting.md`**

Struktur dan isi (bahasa Indonesia, judul `# Troubleshooting Vexis`). Format: tabel **Gejala | Penyebab | Solusi** per area. Intro satu paragraf: kapan memakai dokumen ini + cara mengumpulkan info (paste output error, isi journal `.vexis-agent-journal.jsonl`).

1. **Setup & Build**:
   - `npm install` gagal / error patch-cjs → versi Node < 20, node_modules korup → upgrade ke Node 20+, hapus `node_modules` + `npm ci`.
   - `npm run build` gagal error TS → kode tidak kompatibel / dist lama → `npm run typecheck` untuk detail, pastikan `npm install` selesai.
   - `npm start -- <cmd>` tidak dikenal → belum build → jalankan `npm run build` dulu.
   - Bot tidak jalan tapi tidak ada error → config tidak ditemukan → cek search order (`$VEXIS_CONFIG` → `./vexis.config.json` → `~/.vexis/config.json`).

2. **Config**:
   - `privateKey` invalid → bukan base64/base58 valid → ganti dengan keypair yang benar (base64 atau base58).
   - RPC timeout/rate limit → `rpcUrl` salah atau RPC publik penuh → ganti RPC (mis. provider lain), cek `rpcUrl` ada di config (TIDAK ada env `RPC_URL`).
   - Saldo 0 SOL → wallet belum ada dana → airdrop/fund wallet.
   - Wallet salah → query pakai wallet berbeda → cek `wallet` di config atau argumen perintah.

3. **Telegram**:
   - Bot tidak merespon `/start` → token salah / bot belum di-start → cek `telegramBotToken` (dari @BotFather), buka chat bot dan tekan Start.
   - Notifikasi tidak terkirim → `telegramChatId` salah / bot belum di-start di chat itu → verifikasi dengan @userinfobot, pastikan chat ID numerik.
   - Callback tombol tidak bekerja → bot di-restart / session expired → kirim pesan baru (callback data tidak di-persist).

4. **AI Agent**:
   - Cycle selalu di-skip, journal `llmStatus: "failed"` → LLM error (baseUrl/model/apiKey salah, timeout, rate limit) → cek `agent.llm.*` dan env `OPENAI_API_KEY`; cek timeout `llm.timeoutMs`; pastikan endpoint OpenAI-compatible benar.
   - Banyak `⛔ blocked` → guardrail (cooldown/duplikat/risiko/budget) → baca `blockedReason` di notifikasi/journal; sesuaikan config (mis. `poolCooldownMs`, `risks.*`, `maxSolPerPosition`, `maxTotalSol`, `maxOpenPositions`).
   - Agent tidak pernah open padahal `llmStatus: "ok"` → semua decision `hold`, atau guardrail memblokir → cek journal `rationale` dan `blockedReason`.
   - `llmStatus: "skipped"` terus → nol kandidat setelah screening → longgarkan filter `pools.*` (mis. `minOrganic`, `minTvl`, `minMcap`).
   - Eksekusi `createPosition` gagal (`execution: "failed"`) → SOL tidak cukup / slippage / RPC error → cek saldo, naikkan `slippageBps`, cek RPC.
   - Agent tidak berjalan setelah restart → `enabled` false / state file rusak → `/agent start` lagi; hapus `.vexis-agent.json` hanya jika yakin (state plans/cooldowns hilang).
   - Notifikasi agent tidak muncul → notifikasi selalu dikirim, tapi hanya saat agent aktif → cek `enabled` + `/agent status`.

5. **Web UI**:
   - Halaman blank / minta password terus → password salah → cek `web.password` / `VEXIS_WEB_PASSWORD`.
   - Port bentrok → `web.port` sudah dipakai → ganti port.
   - Data tidak refresh → halaman auto-refresh 30 detik (portfolio/agent) → hard refresh browser; cek server log.

```bash

npm run typecheck
```
